# MASCK ONE Core Sketch Acceptance Checklist

Status: **design-review checklist**

Use this checklist at major whole-product reviews. A “yes” means evidence supports the statement at the review’s claimed maturity level; it must not be checked from optimism.

## Product identity

- [ ] Masck is still understood first as an automated facial-skincare routine, not an LED mask.
- [ ] Supported routine completion requires no manual facial skincare afterward.
- [ ] User can keep their own supported skincare products.
- [ ] Makeup/decorative cosmetics remain outside V1 promise unless deliberately reopened.
- [ ] Facial SPF language is bounded to validated facial coverage.

## Wearable exterior

- [ ] Front reads as one calm continuous premium personal-care volume.
- [ ] No goggle rings/raised eye bezels.
- [ ] No respirator/muzzle/nose-cone cue.
- [ ] No fake vents, front actuator pods or technical decoration.
- [ ] Eye openings remain large, clean and visually thin.
- [ ] Rear architecture does not read as VR halo/counterweight.
- [ ] Visible seams follow genuine manufacturing/service boundaries.
- [ ] CMF matches Mineral Ivory / Warm Porcelain / Soft Stone / Smoke Graphite / Opal Neutral intent.

## On-face experience

- [ ] Placement is obvious and self-guided.
- [ ] No multi-strap fitting ritual.
- [ ] Airway immediately feels open.
- [ ] Forward vision supports intended activities.
- [ ] Hair/ear/jewelry interactions are controlled.
- [ ] Loaded mass/CG/torque include full-routine additions.
- [ ] No unacceptable local pressure or pressure marks.
- [ ] Safe rapid release remains available without power/app.

## Routine

- [ ] CLEAN is controlled/gentle.
- [ ] RINSE/RECOVER actually creates a clean transition.
- [ ] TREAT is optional and not activity theater.
- [ ] Leave-on products are applied without eye/airway contamination.
- [ ] Multiple layers do not simply wipe/mix away.
- [ ] MOISTURISE leaves no manual spreading requirement.
- [ ] SPF, if claimed, has separate application/claims evidence.
- [ ] RELEASE preserves the final layer.

## Product compatibility

- [ ] Exact product identity is separated from physical behavior sensing.
- [ ] Product profile has provenance/evidence state.
- [ ] KNOWN ≠ VALIDATED.
- [ ] Community usage cannot automatically promote safety-critical validation.
- [ ] Reformulation can invalidate prior profile assumptions.
- [ ] Unknown products fail conservatively.
- [ ] AI cannot override deterministic dose/compatibility/safety bounds.

## Dock

- [ ] Bulk skincare is off-head.
- [ ] Wearable carries only session quantities.
- [ ] Dock does not look like a coffee machine/lab rig.
- [ ] Product bays are mistake-resistant and clean to refill.
- [ ] Waste is visually/physically distinct from fresh product.
- [ ] Pickup and return are one-hand, low-friction interactions.
- [ ] Cable is not a daily interaction.
- [ ] Night light/noise behavior is appropriate.
- [ ] Hygiene/service state is inspectable rather than magical.

## Digital UX

- [ ] Home centers on next routine/readiness.
- [ ] Routine editing feels like arranging products/stages, not programming hardware.
- [ ] AM/PM/weekday scheduling works.
- [ ] Today-only override does not rewrite schedule.
- [ ] Normal session does not require phone/cloud.
- [ ] Product scan asks for camera only when needed.
- [ ] No beauty/pore/acne scoring by default.
- [ ] Accessibility does not depend on color/sound alone.

## Sensory quality

- [ ] Opal-neutral status language is restrained.
- [ ] No RGB status strip.
- [ ] No routine chirp sequence.
- [ ] No intentional metallic ping.
- [ ] No loose/rattly/scraping service or control interactions.
- [ ] Deliberate WARM is distinct from incidental device heat.
- [ ] Optical emitters disappear visually when inactive.

## Evidence honesty

- [ ] CAD claims are limited to digital facts.
- [ ] Comfort/feel claims have human/physical evidence.
- [ ] Cleaning/hygiene claims have residue/drying evidence.
- [ ] Optical claims have measured optical/safety evidence.
- [ ] SPF claims have final-film/regulatory-quality evidence.
- [ ] Simulated/development telemetry is not presented as real user data.
- [ ] “Production ready” is used only when production evidence actually exists.
