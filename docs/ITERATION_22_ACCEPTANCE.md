# Iteration 22 acceptance: dual fresh-fluid pump packaging and tubing interfaces

Iteration 22 establishes separate fresh-water and cleanser pump-station identities, preserves the upstream `FRESH_WATER` and `CLEANSER` vocabulary, verifies both storage contracts against the current engineering authority, and binds them to the exact Iteration 20 and 21 architecture hashes and structural-frame fresh-fluid reservation. It defines four non-crossing source-to-pump and pump-to-manifold route interfaces.

The repository contains no controlled supplier package evidence for a selected fresh-fluid pump. Package candidate, envelope, placement, orientation, tubing inner diameter, bend radius, and connector standard therefore remain unresolved rather than being copied from an unverified batch branch. Pressure-flow behavior and dosing accuracy remain validation-gated.

This iteration is a deterministic packaging and interface contract. Routing and service states use exact controlled unresolved values and cannot be caller-promoted. It is not pump selection, metering validation, hydraulic validation, leakage evidence, service validation, or production-component freeze.
