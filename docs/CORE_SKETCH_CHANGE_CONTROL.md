# MASCK ONE Core Sketch Change Control

Status: **concept governance**

The Core Sketch is intended to remain recognizable while detailed engineering is refined. This file defines what constitutes a normal refinement versus a product-concept change.

## Refinements that do not require re-opening the product concept

Provided the user experience and locked invariants remain intact, and released engineering/brand authority and its change process are respected, normal engineering/ID work may refine:

- exact shell dimensions and curvature;
- exact edge radii/gaps;
- number/location of hidden internal components;
- exact retention mechanism;
- exact pumps/valves/actuators;
- exact leave-on deposition mechanism;
- exact material grades/processes;
- exact optical LED count/packaging;
- exact WARM/COOL architecture;
- routine stage durations based on evidence;
- final number of face sizes based on anthropometry;
- dock internal packaging and exact footprint;
- software implementation/model/vendor;
- calibration algorithms;
- service intervals based on testing.

## Changes that require explicit Core Sketch review

The following are product-concept changes, not local refinements:

- dropping whole-routine completion and requiring manual facial skincare afterward;
- silently excluding required facial regions, required stages or difficult product families to make a completion claim pass;
- narrowing support to a trivial cohort or requiring reformulation/dilution of the user's products;
- introducing recurring manual preparation/finishing that materially defeats the complete-routine ownership promise;
- changing the offline promise through compulsory profile freshness/network checks without explicit review;
- forcing MASCK proprietary skincare;
- moving bulk product onto the head such that session-dose architecture is abandoned;
- making phone/cloud/app mandatory for normal use or safe release;
- adopting flexible silicone LED-mask form as the primary archetype;
- adopting VR-style halo/counterweight visual language;
- replacing calm Opal-neutral interaction with RGB/display-heavy interaction;
- adding default skin/beauty scoring or continuous facial surveillance;
- expanding V1 whole-routine promise to decorative cosmetics/makeup;
- claiming body/neck/ear sunscreen completion from facial application;
- removing non-wiping final release requirement;
- turning AI into unconstrained dose/compatibility/safety authority;
- making an optional treatment (LED, WARM, massage) the defining product rather than complete routine;
- adding a large visible technical/service apparatus that materially changes the premium home-object thesis.

## Change record requirements

A proposed Core Sketch change should include:

1. exact invariant being changed;
2. user problem/evidence motivating the change;
3. alternatives considered;
4. effect on complete-routine promise;
5. effect on mass/CG, fit, hygiene, airway/eyes, service, offline/privacy and dock;
6. which backlog items are invalidated;
7. new validation required;
8. explicit decision-log entry if accepted.

Local convenience, a competitor feature or an agent’s aesthetic preference is not sufficient evidence for a Core Sketch change.

The explicit kill/pivot conditions in [the convergence review](CORE_SKETCH_CONVERGENCE_REVIEW.md) require a recorded decision. A failed optional modality first triggers a modality decision; a failed required AM/SPF outcome cannot be hidden by claiming the unchanged morning routine is complete. Unknown preservation, fit or efficacy is an evidence gap, not permission to assign a favorable assumption.
