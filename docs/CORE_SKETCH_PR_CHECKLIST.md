# MASCK ONE Core Sketch PR Checklist

Use in PR descriptions for any change that touches product experience, feature set, dock, skin-contact behavior, treatment sequence, application, retention, HMI, CMF or app/device relationship.

- [ ] Live `main` / owner lineage reconstructed before changes.
- [ ] Relevant Core Sketch backlog ID(s) named.
- [ ] Existing owner PR reused where applicable.
- [ ] Product intent from `CORE_SKETCH_V1.md` preserved.
- [ ] No rejected feature reintroduced unintentionally.
- [ ] Authority/source binding preserved.
- [ ] Protected anatomy/airway/eye boundaries preserved.
- [ ] Full-routine mass/CG impact considered.
- [ ] Skin-contact/hygiene impact considered.
- [ ] Leave-on/non-wiping impact considered.
- [ ] Dock/service implications considered where relevant.
- [ ] Offline/app/privacy implications considered where relevant.
- [ ] AI remains subordinate to deterministic safety.
- [ ] Digital evidence distinguished from physical validation.
- [ ] New concept target is not described as achieved performance.
- [ ] Acceptance criteria/evidence class for backlog closure are explicit.
- [ ] Backlog status updated only if evidence warrants it.

If a PR cannot explain which Core Sketch requirement it advances, it may be local churn rather than useful product progress.
